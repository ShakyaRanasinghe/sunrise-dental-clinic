# Release v1.0.1

- **Date:** 2026-09-02
- **Candidate:** `qa_v1.0.1` (from `dev_v1.0.1`), QA green on `qa`
- **Production tag:** `v1.0.1` (code-only; documentation lives on `dev`/`main`)

## Overview

The v1.0.1 feature wave refines the public portal and the staff portals: every
role now lands on the one doorway that fits its task, the landing and booking
pages are more interactive (no-script, CSS-only), the dentist schedule is
re-ordered around the working day, the admin complaints queue is split into an
open/reviewed flow, and the reception role no longer owns the clinic-phone
screen (the administrator does). A completed visit can no longer be cancelled.

## Features in this release

**Public / patient portal**
- Interactive landing page: expanding services and dentist cards (GAP-PAT-16)
- Booking shows times first, fee details in a CSS-only modal (GAP-PAT-15)
- Versioned footer carries the clinic identity (GAP-PAT-17); account menu when
  signed in; one doorway per task per role
- The portal chooser is gone — the public land straight on the patient door,
  staff doors stay reachable by issued URL (GAP-PAT-14)

**Patient accounts**
- Paged register, a single canonical Sri Lankan phone-number rule, and the
  patient can edit their own details (GAP-PAT-13 area)
- Complaints grouped per dentist behind `<details>` rows on the patient side
  (GAP-PAT-18)

**Dentist portal**
- Schedule re-ordered: today's patients first, finished visits folded below,
  the week ahead last (GAP-DEN-08)

**Reception portal**
- A completed visit can no longer be cancelled (GAP-REC-09)
- The clinic-phone screen is removed from reception; the administrator owns it
  now (GAP-REC-10)

**Admin portal**
- Executive summary cards; the Home nav tab removed (GAP-ADM-08)
- Complaints queue splits into open cards and a collapsed, reviewed list
  (GAP-ADM-09)

**Platform**
- Interactive, no-script help page
- Smoke script updated to the new navigation (`/login` chooser dropped) and to
  assert the critical warning on a pending visit
- Release tooling hardened: the `Release` workflow verifies prod's shipped code
  is byte-identical to the latest `qa_v*` tag before packaging, and skips the
  CI `.github/` folder which is not QA'd product code

## What is not in this release

- Dentist profile photos / patient-facing dentist avatars (tracked as
  GAP-PAT-13 / GAP-DEN-07, specified not yet built)
