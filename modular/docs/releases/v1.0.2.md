# Release v1.0.2

- **Date:** 2026-09-03
- **Candidate:** `qa_v1.0.2` (from `dev_v1.0.2`), QA green on `qa`
- **Production tag:** `v1.0.2` (code-only; documentation lives on `dev`/`main`)

## Overview

The v1.0.2 UX polish batch refines the public page, sign-up, profile, booking
and help flows: services no longer push booking links, dentist cards render
whole, every role gets its own help page and dashboard Help entry, the
create-account form is wider and shorter, the patient profile carries diagnosis
details, booking names the dentist and leads with times, treatments open info
sub-windows, and every save confirms in a success sub-window. The footer reads
Version, and the sign-in/sign-up accents moved from orange to blue.

## Features in this release

**Public page**
- Service descriptions without the mid-page "Book this service" link
  (GAP-PAT-22)
- "Our dentists" cards render fully, no expand toggle (GAP-PAT-23)

**Help, per role**
- One help page per role under `/help/<role>`, each grounded in its role SRS;
  every dashboard nav ends in its own Help (GAP-FTB-12, GAP-PAT-24)
- Staff sign-in screens link their own help; the `/staff` portal offers none;
  reception register/walk-in link the reception help
- Contents cards headed "Help topics" on the shared and role pages (GAP-FTB-13)

**Patient accounts**
- "Raise a concern" opens straight into the visit list (GAP-PAT-25)
- Create-account card wider with paired fields; the "Nothing medical" notice
  and the phone helper sentence removed (GAP-PAT-26)
- Profile carries the patient's own diagnosis/history details (GAP-PAT-27)

**Booking**
- One card headed with the doctor's available times, treatment picker below;
  submit names the dentist; the re-picker card is gone (GAP-PAT-28)
- Each treatment has an info mark opening its description (GAP-PAT-29)

**System-wide**
- Read-only-by-default edits with "Successfully updated" sub-windows on the
  profile, dentist phone, clinic identity and treatment catalogue (GAP-FTB-14)
- Footer reads "Version v…" (GAP-FTB-11); auth accents moved to blue

## What is not in this release

- Dentist profile photos / patient-facing dentist avatars (tracked as
  GAP-PAT-13 / GAP-DEN-07, specified not yet built)
- Bootstrap theming: evaluated and declined — Bootstrap's interactive
  components need a JavaScript framework, which the client constraint
  (srs.md §2.4, no JavaScript framework) forbids
