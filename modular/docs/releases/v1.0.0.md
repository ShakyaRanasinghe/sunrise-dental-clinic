# Release v1.0.0

- **Date:** 2026-08-28
- **Candidate:** `qa_v1.0.0` (from `dev_v1.0.0`), QA green on `qa`
- **Production tag:** `v1.0.0` (code-only; documentation lives on `dev`/`main`)

## Overview

The Sunrise Dental Clinic application — a single self-contained Java WAR serving
its own server-rendered pages with no frontend build and no external
application server beyond Apache Tomcat at runtime. Deployed on Render from the
`prod` branch.

## Features in this release

**Public / patient portal**
- Landing page with a hero banner and clear calls to action
- Self-registration with client-side validation, a show/hide password (eye)
  control on every password field, and server-side re-render on error
- Patient sign-in straight from the header; booking of dentist appointments;
  profile; complaints
- Public "Our dentists" section showing dentists, specialisations and ratings

**Staff portals** (reachable by issued URL, not advertised publicly)
- **Reception:** daily schedule, patient search, booking control, billing
- **Dentist:** schedule, published availability, completing appointments
  (guard rails prevent completing unborn future appointments)
- **Admin:** account management, complaints, reports (portals are role-staff
  only; the public chooser presents just the patient door, GAP-PAT-14)

**Scheduling, billing and reporting** (in-module services)
- Appointment booking against published availability; day view
- Billing with revenue splitting per channel and treatments
- Reporting across the practice

**Platform**
- Four-role authentication (patient/receptionist/dentist/admin) backed by
  stored hashed passwords and session control; role-based navigation
- Module boundaries enforced (web tier cannot reach the data tier); 290+ tests
  covering access, scheduling, billing, reporting, boundaries and end-to-end
  page/view rendering
- Local dev via Docker (`scripts/dev-up.sh`, `scripts/redeploy.sh`)

## Deliverable alongside this release

- GitHub release `v1.0.0` with the built `clinic.war` attached (produced by the
  `Release` workflow on the tag push)
- QA pipeline (`QA` workflow) running build + tests + module boundaries + smoke
  on every push to `main`/`qa`/`develop`

## What is not in this release

- Dentist profile photos / patient-facing dentist avatars (tracked as
  GAP-PAT-13 / GAP-DEN-07, specified not yet built)
