# Release v1.0.4

- **Date:** 2026-09-04
- **Candidate:** `qa_v1.0.4` (from `dev_v1.0.4`), QA green on `qa`
- **Production tag:** `v1.0.4` (code-only; documentation lives on `dev`/`main`)

## Overview

The v1.0.4 wave gives staff username sign-ins, bare staff doors, and sortable,
filterable tables: reception, dentists and administrators sign in with usernames
(email still works), staff logins show no public navigation, sign-out returns
staff to the staff portal, Accounts filters by role, and the day, billing and
complaints tables sort server-side. It also fixes a schedule crash on pending
treatment-less visits found live.

## Features in this release

**Staff sign-in (GAP-ADM-12)**
- Reception, dentist and administrator portals ask for a username; email still
  works as fallback; patients stay email-only
- Usernames provisioned by the administrator (validated, unique) and listed on
  Accounts; existing staff backfilled; demo credentials and docs read as usernames

**Staff doors (GAP-ADM-14)**
- Staff logins and `/staff` render the bare branded bar — no public navigation
- Signing out lands staff on `/staff`, patients on the public home page

**Tables (GAP-ADM-13)**
- Accounts filters by role; reception day and billing tables sort by time
  asc/desc and dentist; complaints queue sorts newest/oldest — all server-side

**Fixes**
- JSP expression-language crash on pending treatment-less visits: record
  components resolve only as method calls, with a JSP-wide regression test
- Public hero banner replaced

## What is not in this release

- Dentist profile photos / patient-facing dentist avatars (tracked as
  GAP-PAT-13 / GAP-DEN-07, specified not yet built)
- Older open gaps (GAP-PAT-04/05/06, GAP-REC-06, GAP-DEN-03/04/07, GAP-ADM-02..05)
